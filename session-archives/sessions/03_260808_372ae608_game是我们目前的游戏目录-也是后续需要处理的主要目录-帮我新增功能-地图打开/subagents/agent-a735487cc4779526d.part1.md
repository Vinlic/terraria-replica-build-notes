````
### 4.3 静止判定与 kill（Liquid.cs:652-671）
```csharp
if (tile5.liquid != liquid /*进入时快照*/) {

## 5. DelWater（Liquid.cs:1117-1213）

被移出列表时的收尾，**含多处再唤醒**：
- `liquid < 2` → 清零本格；左右 `<2` 也清零，否则 `AddWater`（L1125-1137）。
- `liquid < 20` 且（左右更低 或 下方不满）→ 本格清零（残余水膜抹除，L1138-1142）。
- `liquid >= 20` 且下方未满且下方可通行 → `kill=0; return`（**留在列表里**，不算静止，L1143-1147）。
- `liquid < 250 && tile[x,y-1].liquid > 0` → `AddWater(x, y-1)`（L1148-1149）。
- 左/右格 `0 < liquid < 250`、可通行、与本格不等 → `AddWater`（L1156-1159）。
- `lava()` → `LavaCheck(x,y)` + 3×3 内草方块转泥土：type 2/23/109/199/477/492 → 0；60/70 → 59（L1160-1187）。
- `honey()` → `HoneyCheck(x,y)`（L1188-1189）。
- swap-remove：`Main.liquid[l] = Main.liquid[--numLiquid]`（L1193-1197）。
- 尾部：藻类 `CheckAlch`，荷叶(518) `CheckLilyPad`（L1198-1212）。

## 6. 液体交互（重点）

### 6.1 LavaCheck(x, y)（Liquid.cs:888-1016）——(x,y) 是岩浆格
前置：`WorldGen.SolidTile(x,y,false)` 则直接返回（L898）；地狱沙漠特例 L890-897。

**情形 A：左/右/上方有非岩浆液体**（L905-960）
```csharp
num = tile[x-1,y] + tile[x+1,y] + tile[x,y-1] 中所有 !lava() 的 liquid 之和（并清零这些格）
Type = 56 (Obsidian)；若三者中任一 honey() → Type = 230 (Crispy Honey Block)
if (num < 24) return;                       // 量太少：水被吃掉但不生成方块
if (本格 active && tileObsidianKill[type]) KillTile(x,y);
if (WorldGen.getGoodWorldGen) { ... 类型互换 ... return; }   // L934-940
if (tile5.active()) return;                 // 本格已有方块 → 什么都不生成
tile5.liquid = 0; tile5.lava(false);        // 岩浆被消耗
PlaceTile(x, y, Type); SquareTileFrame;
```
生成位置：**岩浆所在格**。

**情形 B：仅下方有水/蜂蜜**（L961-1015）
```csharp
tile4 = tile[x,y+1]
若 tile4 是可切割植物 / tileObsidianKill → KillTile(x, y+1)
容器特例 L965-967
if (!tile4.active() | 容器) {
    if (tile5.liquid < 24) { tile5.liquid = 0; tile5.liquidType(0); return; }  // 岩浆<24：直接蒸发
    Type = 56；tile4.honey() → 230
    tile5.liquid = 0; tile5.lava(false);     // 岩浆消耗
    tile4.liquid = 0;                        // 水也消耗
    PlaceTile(x, y + 1, Type);               // 生成在水那一格（岩浆下方）
}
```
**注意**：Liquid.cs 中**没有"生成石头"的分支**。小于阈值（24）时液体直接消失，不产 stone；石头生成只在别处（如岩浆直接放置 WorldGen.PlaceTile 的转换），移植时不要臆造。交互产物只有 **56=黑曜石、230=脆蜂蜜块**，阈值 **24**。

### 6.2 HoneyCheck(x, y)（Liquid.cs:1018-1115）——(x,y) 是蜂蜜格
前置 `SolidTile` 返回（L1020）。

**情形 A：左/右/上方有水（liquidType()==0）**（L1028-1069）
```csharp
num = 三邻中水的 liquid 之和并清零；邻中有 lava() → flag=true（仅决定音效）
if (num < 32) return;                       // 阈值 32（蜂蜜用 32，岩浆用 24！）
if (本格 active && obsidianKill) KillTile(x,y);
if (tile5.active()) return;
tile5.liquid = 0; tile5.liquidType(0);
PlaceTile(x, y, 229 /* Honey Block */);
```
**情形 B：仅下方有水**（L1071-1114）：植物/obsidianKill 处理同上；`tile4.active()` 则 return；`tile5.liquid < 32` → 蜂蜜清零消失；否则两格清零，`PlaceTile(x, y+1, 229)`。

### 6.3 WorldGen.PlaceLiquid（WorldGen.cs:375-412）——放置时直接冲突
```
同种或空 → 直接累加（溢出截到 255）
水+岩浆 → 56 黑曜石；水+蜂蜜 → 229 蜂窝块；岩浆+蜂蜜 → 230 脆蜂蜜块
（L397-402），生成后本格 liquid=0、liquidType(0)、PlaceTile
```

### 6.4 交互触发的方向语义
- 由**岩浆格/蜂蜜格自己的 Update** 触发（L327-339 / L350-362），检查自己四邻。
- **水不会主动检查**；水格发现邻居是岩浆/蜂蜜时只做 `AddWater`（L342-349, L365-372）唤醒对方。
- 判定顺序：**先左右、再上、最后下**（L905 的 || 链与 L961 的 else；HoneyCheck 同构）。
- 消耗量：A 案消耗"岩浆格全部 + 周围非岩浆液体全部"，B 案消耗"岩浆格全部 + 下方液体全部"，产物只有 1 格方块。

## 7. 挖掘/放置的唤醒机制

- **统一入口是 `Liquid.AddWater(x,y)`**（Liquid.cs:835-872）。条件（L838）：tile 非空、未 `checkingLiquid`、`5 <= x < maxTilesX-5`、`5 <= y < maxTilesY-5`、`liquid != 0`、非实心（type 546 例外）。若 `numLiquid >= curMaxLiquid-1` → 走 `LiquidBuffer.AddBuffer`（LiquidBuffer.cs:15-23，上限 49998）；否则置 `checkingLiquid(true)`、`skipLiquid(false)`、`kill=0`、`delay=0` 入列（L846-852），服务器还要 `NetSendLiquid`（L853-854）。随后做 TileObjectData 的水/岩浆死亡检查，必要时 `KillTile`（L855-871）。
- **挖掘/放块真正的唤醒点在 `WorldGen.TileFrame`**（WorldGen.cs:49664-49665）：
```csharp
if (tile1.liquid > 0 && Main.netMode != 1 && !WorldGen.noLiquidCheck)
    Liquid.AddWater(i, j);
```
`KillTile`/`PlaceTile`/`SquareTileFrame` 都会走到这里。`WorldGen.noLiquidCheck=true`（WorldGen.cs:49015）期间不唤醒。
- **KillTile 本身不清液体**：只在 type 58（Hellstone）且 `y > UnderworldLayer` 时 `lava(true); liquid = 128`（WorldGen.cs:38140-38144）。
- **水桶吸水**（Player.cs:30032-30065）：清目标格后 `AddWater`，并把 3×3 内同种液体抽干合并。
- **水桶倒水**（Player.cs:30069）：目标格 `liquid >= 200` 或实心（546 例外）则拒绝。
- **WorldGen.EmptyLiquid**（WorldGen.cs:356-373）：`Clear(Liquid)` + `SquareTileFrame` + `AddWater`。
- **LiquidBuffer**（LiquidBuffer.cs）：溢出时的候补队列，每清扫轮回灌（§2.2 第 2 步）。

## 8. WorldGen / 载入阶段的沉降

### 8.1 Liquid.QuickWater(verbose, minY, maxY)（Liquid.cs:85-103）
```csharp
minY/maxY 缺省 → 3 / maxTilesY-3
for (y = maxY; y >= minY; --y)            // 自底向上
    for (x = 4; x < maxTilesX-4; ++x)
        if (tile[x,y].liquid != 0) SettleWaterAt(x, y);
```

### 8.2 SettleWaterAt（Liquid.cs:105-212）——直接搬运式沉降
把本格液体暂存 `liquid`、`num1=liquidType()` 后清零（L115-117），然后：
1. **垂直下落**（L121-130）：`Y++` 直到下方是实心/有液体/到边界；`WorldGen.gen && 非蜂蜜 && Y > WorldGen.waterLine` → 类型改成岩浆(1)（L129-130）。
2. **蛇形横向铺开**（L138-195）：`num2` 为方向(±1)，`num3` 为步数。沿当前行找空位（L140-144 记录最后空位 `num4/num5`）；途中若 `(X+num3*num2, Y+1)` 有**同类型且 <255** 的液体则直接灌入（L150-159），灌完 `liquid==0` 即结束；若下方可掉落则跳出内层循环进入下一轮 `++Y`（L193-194, L196-202）；否则按 flag3/flag4 折返方向（L170-189）。
3. 落点写回（L204-205）：`tile[X,Y].liquid = liquid; liquidType(num1)`。
4. **落地即交互**（L206-210）：`liquid > 0` 时 `AttemptToMoveLava` / `AttemptToMoveHoney`（L248-280 / L214-246）：按 左→右→上→下 的顺序找异种邻居，对岩浆/蜂蜜所在格调 `LavaCheck`/`HoneyCheck`。

### 8.3 WorldGen.WaterCheck()（WorldGen.cs:48955-49009）
全图重扫，重建活动列表：清 `numLiquid`/`numLiquidBuffer`，`y` 自底向上、`x` 升序；实心格内液体清零（L48966-48967）；下方可流且未满 → `AddWater`（下方 `>250` 先补满 255，L48981-48986）；左右液面不等 → `AddWater`；岩浆格四周有非岩浆 → `AddWater`（L48994-49004）。

### 8.4 调用时序
- **世界生成 pass "Settle Liquids"**（WorldGen.cs:7399-7431 与 10254-10279）：`worldGenTilesIgnoreWater(true)` → `QuickWater(3,-1,-1)` → `WaterCheck()` → `quickSettle=true` → 外层 10 轮，每轮 `while (numLiquid>0) UpdateLiquid()` → 每轮末 `WaterCheck()` → 复位。
- **生成地狱后**：`QuickWater(-2,-1,-1)`（WorldGen.cs:6003）。
- **读档**（IO/WorldFile.cs:365-389）：`waterLine=maxTilesY` → `QuickWater(2,-1,-1)` → `WaterCheck()` → `quickSettle=true` → `while (numLiquid>0 && 迭代<100000) UpdateLiquid()`（带进度条）→ `quickSettle=false` → 再次 `WaterCheck()` → `gen=false`。

## 9. 移植 TS 的最小公式速查

侧向: M=round((sum(参与格)+ (cur<3?-1:0)) / N); 各格写 M;

```
````
