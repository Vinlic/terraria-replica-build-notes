## 7. TS/Vite 移植要点建议

1. **数据模型**：`Map<string /*fullKey*/, string>` + `Map<string /*category*/, string[] /*subKeys*/>`（后者支撑 `RandomFromCategory` / `IndexedFromCategory` 的取模循环）。
2. **键生成**：`fullKey = category + "." + subKey`；名字类键需一张 `ID → 常量名` 映射表（等价 C# 反射），建议从 `ItemID`/`NPCID`/`ProjectileID`/`BuffID` 常量文件生成。
3. **必须实现的三种模板语法**（LocalizedText.cs L12 / VariableText.cs L29）：
   - `{0}` `{1}` … → `string.Format` 位置参数（注意 `{{` 转义与 `{0,5}` 对齐格式，可用 JS 库或自实现）
   - `{VariableName}` / `{Obj.Prop}` → 命名替换（全局表 + 传入对象属性）
   - `{?Cond}` / `{!Cond}` → 条件显示（`ConditionsMet` 决定整条是否可用，如 `TownNPCMood`、`Bestiary_ItemDropConditions`）
   - `{$Category.SubKey}` → 跨键复制（加载后统一后处理，迭代至稳定）
   - 变体键 `ItemName.X$Gender` → 单独变体表
4. **回退加载顺序必须保留**：`重置值为 key → en-US → 目标语言`，这样翻译缺 key 时自动落英文而非显示 key。
5. **解析器注意**：反编译出的 `.json` 资源含**尾逗号**（`{"A": 1,}`），TS 侧 `JSON.parse` 会失败，需先用 `text.replace(/,(\s*[}\]])/g, '$1')` 清洗（我验证过该正则对全部 en-US/zh-Hans 文件有效）。
6. **持久化**：localStorage/文件存 culture 字符串（`zh-Hans`），读取时兼容数字 legacyId；显示名从 `Language.*` 类别取（每种语言自带本地化名）。
7. **缺失键策略**：`GetText` 缺失时返回"键名本身"（LanguageManager.cs L446–453），`Exists` 用于显式探测（`EmojiName` 的 `leaveMissingEntriesBlank` 模式依赖它）。
