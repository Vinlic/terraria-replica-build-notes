# 二、重点问题解答

## Q3：哪些 pass 写到天空？

真正写天空的只有 4 个注册点：

| pass | 行号 | 写入内容 |
|------|------|---------|
| FloatingIslands | 12976 | 岛体本体（云块/雪云块/沙漠云块 tile，即 `TileID.Sets.Clouds` 系列）+ 天空湖。位置算法：x 取宽度 10%–90%（避开中心 ±90~180 格），y = `genRand.Next(90, 地表上方100格内)` 再钳制到 `≤ GenVars.worldSurfaceLow - 50`，即**全部在地表线以上** |
| FloatingIslandHouses | 17971 | 对 `GenVars.skyLake[i]==false` 的岛调 `IslandHouse()`（79819 行）建房 |
| Skyblock | 11534 | 仅天空岛种子，`GenerateSkyBlockWorld()` |
| CloudLake | helper | `WorldGen.CloudLake`（79068 行），天空湖，由 FloatingIslands 内部调用 |

FloatingIslands 调用的天空绘制 helper：
- `WorldGen.CloudIsland`（78618）、`SnowCloudIsland`（77746）、`DesertCloudIsland`（78182）——标准/雪原/沙漠风格云岛
- `WorldGen.CloudLake`（79068）——天空湖
- `WorldGen.IslandHouse`（79819）——浮空岛房屋（岛心圆盘 tile 202、墙 82，检查周围无地牢墙才放置）

**没有独立的 generateClouds / Clouds pass**。原版世界里"云"分两类：
1. **云块 tile**（可站立、属 `TileID.Sets.Clouds`）——由 FloatingIslands pass（12976）放置，这是世界数据的一部分；
2. **背景飘动云**（`Main.numClouds`、`Cloud.resetClouds()`）——纯渲染对象，在 `RandomizeWeather()`（WorldGen.cs:7737）里初始化，**不属于任何 worldgen pass**。

## Q3b：原版有没有"最后清理天空/浮空块"的 pass？

**没有通用天空清理 pass。** 结论依据：

- 代码中不存在 `ClearUnequal` / `RemoveDungeons` / `ClearAboveSurface` 之类的标识符（全文件 grep 无结果）。
- 最后一个 pass 是 `FinalCleanup`（22304），但它**只做定点修补，不做天空清扫**。其逻辑（22304–22659）：
  - `FillWallHolesInArea(0, 0, maxX, worldSurface)`——地表以上区域补墙洞；
  - 对悬浮的沙/淤沙/雪泥/泥/石（tile 53/112/234/224/123）向下找支撑，找不到就转换成对应"悬挂变体"（397/398/399/147/石）——即让它们合法悬挂而非删除；
  - 巨石(2×2)无支撑时整块落地或替换；
  - 移除云岛外孤立液体、处理地牢内液体、画作无墙支撑处理等。
- 其它清理 pass 也都不扫天空：`QuickCleanup`（17987，只删 `TileID.Sets.CanBeClearedDuringGeneration` 的悬空坡度/半砖块）、`GravitatingSandCleanup`（15198，只针对沙）、`TileCleanup`（21327，清坡度/水中自毁图格/放滴管）、`DirtWallCleanup`（15310）、`BrokenTrapCleanup`（22283）、`BeachesAndOceanCleanup`（14947）、`RemoveSurfaceWaterAboveSand`（16295）。

也就是说：**原版靠"地表以上从 TerrainPass 起就保持空气"这一不变式来保证天空干净，从不做事后清扫**。天空中的内容全部是 FloatingIslands/FloatingIslandHouses 主动、受保护地写入的。

## Q4：TerrainPass 如何处理地表以上空间？

**始终空气（直接置 inactive），不是先填后清。** 见 `~/Project/GLM/SandboxWorld/Terarria1456/Terraria.GameContent.Biomes/TerrainPass.cs` 的 `FillColumn`（246–271 行）：

```csharp
for (int i = 0; (double)i < worldSurface; i++)
{
    Main.tile[x, i].active(active: false);   // 地表以上：直接清空为空气
    ...
}
// worldSurface ~ rockLayer: type = 0 (Dirt)；rockLayer 以下: type = 1 (Stone)
```

每列从 y=0 到 worldSurface 无条件 `active(false)`（不填任何图格），worldSurface 到 rockLayer 填 Dirt(0)，rockLayer 以下填 Stone(1)。ApplyPass 结束时（206–243 行）写入全局层位：`Main.worldSurface`、`Main.rockLayer`、`GenVars.waterLine`、`GenVars.lavaLine` 等，后续所有 pass 以此为天空/地下分界。

## Q5：液体 pass 与云的位置

- **液体**：两处。`SettleLiquids`（16215，第 53 个 pass，约在序列 48% 处——位于丛林神龛之后、绿洲/SmoothWorld 之前）和 `SettleLiquidsPart2AndNotTheBees`（21051，第 101 个 pass，约 92% 处——位于蜂蛹之后、仙人掌/棕榈/珊瑚之前）。前者是真正的沉降循环（`Liquid.QuickWater(3)` + 10 轮 `Liquid.UpdateLiquid()`），后者是收尾沉降。另外注水发生在更早的 `Lakes`（14613，第 33 个）。
- **天空云**：没有 pass（见 Q3）。云块 tile 在 `FloatingIslands`（12976，第 26 个 pass，约 24% 处，紧跟花岗岩洞之后、DirtToMud 之前）；背景飘云与 worldgen 完全无关。

## 补充：Meteor（流星）

**不属于世界生成管线。** `WorldGen.dropMeteor`（6196）/`meteor()`（6318）是运行时事件（砸祭坛后掉落、陨石雨 `StartMeteorShower` 6189）。唯一在生成期出现的位置是 `DoNoSurface()`（907–923 行）——"无地表"秘密种子的后处理步骤，用 `dropMeteor(spawnUnderGround: true)` 造地下陨石，它在 AddPasses 之外的 `Finish()` 阶段流程中调用，也不是注册的 GenPass。
