## 2. 疑似清单(按严重度)

### 高:状态机死态(等值门永不命中)

**① dandelionAI — 行 3664,ai0 读点 3671、3674 — 喷籽功能全灭(空转)**
`if (this.ai0 === 0)` / `else if (this.ai0 === 1)` 两门在 -1120 下全不命中,方法每 tick 直接走完什么都不做:蒲公英**永远不会喷籽**(836 号弹永不生成),ai1 计数也永不启动。出生路径无解:`VanillaSpawner.ts:2104` 走 `D(628)` 不传 ai0,-1120 必然流入。
修法:入口加 `if (this.ai0 < 0) this.ai0 = 0;`(3667 的 early-return 之后)。

**② birdAI — 行 3070,ai0 读点 3073(`===0`)、3087(`===2`)— 地面/降落态全死(永久滞空)**
两门都不命中 → 落入 3095-3136 的飞行态,而飞行态**没有任何写 ai0 的出口**(3081 写 1 只在态 0 内,3092 写 0 只在态 2 内,均不可达)。后果:所有鸟出生即永久飞行,地面踱步(原版 ai[0]=0 出生态)与降落回地(3092)成为死代码,行为与原版"落地啄食→受惊起飞"完全不符。出生路径不传 ai0,必然触发。
修法:入口加 `if (this.ai0 < 0) this.ai0 = 0;`。

### 中:振荡计数器从 -1120 爬起(相位错误 + 延迟 ~1120 tick)

三个同构问题:原版从 0 起 `+1` 到 200 后翻 -200,**只钳上界不钳下界**,负值直接泄漏。共同症状:进入正常 ±200 振荡前有一段"单向偏置漂移"(vy 恒 -、vx 恒 +,因为 `|ai0|>100` 恒真),约 18-22 秒后才进入正常循环。

**③ swarmerAI — 行 2483,ai0 读点 2521-2526**
`ai0 += 1`(2521)、`vy += ai0>0?…`(2523)、`vx += |ai0|>100?…`(2524)、`if (ai0>200) ai0=-200`(2522)。从 -1120 爬到 200 需 1320 tick;期间噬魂怪/蜜蜂/小鬼等近距摆动恒为"vy-0.023/vx+0.023"单向漂移。影响 2517-2519 的全部摆动族(eater 族 dist>100 门 + 蜂族无条件)。
修法:入口或摆动分支加 `if (this.ai0 < -200) this.ai0 = 0;`。

**④ cursedSkullAI — 行 2639,ai0 读点 2651-2654**
同构,步长 0.9:`ai0 += 0.9`,从 -1120 到首次翻 -200 约 1244 tick,期间(dist<250 分支)恒 vy-0.019/vx+0.019。诅咒头骨/巨型诅咒颅悬停抖动相位错误。
修法:同上。

**⑤ wallCreeperAI — 行 1761,ai0 读点 1785-1788(`!los` 分支)**
`ai0 += 1`(1785)、`vy += ai0>0?…`(1786)、`vx += (ai0<-100||ai0>100)?…`(1787)、`ai0>200→-200`(1788)。-1120 需 920 tick 才爬到原版下界 -200,期间无视线漂移恒 vy-0.023/vx+0.023(0.023 钳 3 上下),爬墙蜘蛛"失视振荡"长时间偏置。
修法:同上。

### 低:固定偏置 / 条件性风险

**⑥ seahorseAI — 行 3843,ai0 读点 3845、3851-3852、3855、3862、3873-3874 — 方向固化(约 92°,近垂直向下)**
3845 的自愈条件 `ai0 === 0 || Math.abs(ai0) < 0.01` 抓不住 -1120(abs=1120)→ 角度保持 -1120 rad(mod 2π ≈ 1.6 rad ≈ 92°)→ 所有海马出生后朝**几乎正下方**游;直到撞底反射(3874)或 450-600t 冷却后 spd>3 重掷(3855)才恢复随机。非死态,是确定性方向偏置 + 随机化延迟。出生路径(`VanillaSpawner.ts:1499`)不传 ai0,必然触发。
修法:3845 改 `if (!this.aiInit) { aiInit=true; ai0=rand…; }` 或条件加 `ai0 < 0`。

**⑦ plantAI — 行 2403,ai0 读点 2406-2407、2424 — 条件性即死(非出生路径安全)**
入口 `if (ai0 < 0 || ai1 < 0 || !inBounds || tile==0) → dead`。ai0<0 是"锚点失效"自语义,但与"未初始化 -1120"不可区分。自然刷怪路径安全:`VanillaSpawner.ts:424` 对 43/101/175/259/260 全部传锚点格(1782/1798/1885/1901/2025)。但任何绕过该路径的植物生成(`Enemy.fromVanilla`(460)/`Game.spawnNpcByVanilla`(Game.ts:10808)/微光 Transform 等,均不设 ai0)会在第一个 AI tick **立即自灭**。
修法:入口区分"未初始化"与"锚点失效":`if (this.ai0 === -1120) { ai0 = Math.floor(cx/TILE); ai1 = …; }`,或 fromVanilla 里对 aiStyle 13 补锚点。

**⑧ towerAI — 行 4468,ai0 读点 4545、4582-4583 — 无害(相位偏移)**
`vy = sin(2π·ai0/300)·0.5`(4545)+ `ai0++; ai0>=300→0`(4582-4583)。300 tick 恰为一个完整正弦周期,翻回 0 无跳变;-1120 只产生悬停动画相位偏移。无需修(若求干净可入口归一)。

**⑨ flyingSwarmerAI — 行 2252,ai0 读点 2260、2261、2264 — 侥幸无害(建议留注释)**
ai0 是视线计时器。2261 `else if (ai0 > -1000) ai0 -= 1` 在 -1120 下永假 → ai0 冻结;但唯一消费点是 2264 `ai0 <= 0`(失视逃逸门),-1120 与原版初值 0 的判定结果一致,且 2260 有视线即重置 90。行为等价,属"意外安全",建议加一行归一注释防后续误改。
